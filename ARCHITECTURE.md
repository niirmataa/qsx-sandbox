# Architecture

QSX separates controller state, a temporary private import staging tree, and the authoritative guest workspace. `workspace` reads the source, reconstructs Git safely in staging, creates the technical baseline/task branch, and records controller metadata. `GuestProvisioner` verifies an operator-downloaded, versioned base image by SHA-256, converts it into an independent 60 GiB QCOW2 (no backing chain), and creates a read-only NoCloud ISO. On first boot cloud-init copies the Git tree to `/home/agent/workspace/<project>` on that disk and powers off. The operator then detaches the ISO before agent work. The source is never attached to the domain.

After provisioning, the staging tree is not an agent workspace and is never used as checkpoint truth. For checkpoint/export, the production path requires SHUTOFF and uses libguestfs `virt-copy-out --ro` to inspect/extract the guest workspace without mounting an untrusted guest filesystem in the host kernel. The disk checkpoint therefore contains the guest OS, Git repository, commits, and dirty files together. Cloud tests prove image/ISO construction and offline copy mechanics, but full guest restore remains host-BLOCKED.

`LibvirtBackend` uses explicit `virsh qemu:///system` operations for define, start, status, clean shutdown, and import-media detach. Start refuses absent KVM; there is no fake or TCG fallback. Domain XML attaches only the private disk and temporary read-only import ISO, with no host filesystem or network interface. `offline` and `openai` remain policy labels until reviewed host enforcement is implemented and accepted.

Checkpoint manifests are atomic and include disk SHA-256, Git observation, dirty status, ancestry, and validation status. Restore validates the ID and containment, complete manifest, image hash, and `qemu-img check`; it then makes a UUID-suffixed rescue copy before atomic replacement.

Research Memory is a separate controller-side append-only hash chain, never part of disk restore. It stores agent claims, controller observations, independent evidence, lifecycle events, negative results, Git/checkpoint links, and handoffs. CHANGELOG/MEMORY/LIFE/CONTEXT are atomic generated views, not competing sources of truth. Resume reads controller task identity and does not switch the stale import checkout. Checkpoint ancestry follows the controller's current pointer, so CP-A → CP-B → rollback CP-A → CP-C makes A the parent of C while preserving all lifecycle events.
